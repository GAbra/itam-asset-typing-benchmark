# ITAM Asset Typing Benchmark

[![CI](https://github.com/GAbra/itam-asset-typing-benchmark/actions/workflows/ci.yml/badge.svg)](https://github.com/GAbra/itam-asset-typing-benchmark/actions/workflows/ci.yml)
[![MIT](https://img.shields.io/badge/license-MIT-0f766e)](LICENSE)

**Один набор правил. Три движка. Воспроизводимый эксперимент по типизации IT-активов.**

[English](README.md) · [Методика](docs/METHODOLOGY.md) · [Исходные результаты](benchmark-results) · [Протокол запуска](docs/TEST_PROTOCOL.md)

Сравниваются HashMap + BitSet, скомпилированные выражения CEL и DMN / Apache KIE. Все движки используют один канонический набор из 14 правил, одинаковое извлечение 22 признаков и общий механизм разрешения конфликтов.

## Результаты сохранённого эксперимента

На 1 000 000 синтетических активов: **0 расхождений между движками и 0 расхождений с метками генератора**.

| Движок | Медиана, активов/с | Время на актив |
|:--|--:|--:|
| HashMap + BitSet | **294 569** | **3,395 мкс** |
| CEL | 97 462 | 10,260 мкс |
| DMN / KIE | 40 773 | 24,526 мкс |

![Производительность по размерам набора](docs/assets/throughput.svg)

Цифры взяты из [сохранённых JSON](benchmark-results/benchmark-1000000.json): пять измеряемых проходов, два прогрева на первых 5 000 записях. Параметры исходной машины и точной JVM не сохранены. Эти результаты характеризуют конкретный синтетический эксперимент; переносить абсолютные скорости на другие машины и production без нового измерения нельзя.

## Что делает проект

Синтетический генератор создаёт нормализованные контексты с признаками, похожими на данные AD, Nmap, Kaspersky Security Center, Zabbix и SIEM. Результат — тип, подтип, статус и идентификаторы выигравших правил: например, `DEVICE / SERVER` или `ACCOUNT / SERVICE_ACCOUNT`.

Raw samples иллюстрируют форматы. Импорт исходных выгрузок, подключение к продуктам, дедупликация активов и запись в БД не реализованы. См. [архитектуру](docs/ARCHITECTURE.md) и [происхождение данных](data/SOURCES.md).

## Запуск

Нужен Docker с Compose в режиме Linux containers. В каталоге репозитория:

```powershell
.\run-quick-demo.ps1
```

Linux / macOS:

```sh
sh run-quick-demo.sh
```

Скрипт собирает проект, запускает тесты, генерирует 10K активов, проверяет эквивалентность движков и метки, затем выполняет benchmark и экспортирует DMN. При ошибке проверки benchmark не запускается. Новые отчёты сохраняются в `results/local/`; исторические JSON не перезаписываются.

При недоступности Docker registry используйте [готовый runtime из CI](docs/PREBUILT_RUNTIME.md). Для Java 21 + Maven 3.9+ и наборов до 1M есть [полный протокол](docs/TEST_PROTOCOL.md).

## Как интерпретировать результат

Измеряемый участок включает извлечение признаков, исполнение правил, разрешение конфликтов и вычисление checksum. Чтение JSONL и инициализация движков находятся за пределами таймера.

Порядок движков фиксирован: BitSet → CEL → DMN. Они работают в одной JVM и разделяют JIT, GC и кэши. Прогрев охватывает только первые `min(batch, 5000, max)` записей. Это пакетный функциональный benchmark, не JMH; доверительные интервалы и независимые JVM-процессы пока отсутствуют.

Совпадение результатов не исключает общую ошибку в правилах, extractor или resolver. Метки генератора отражают его предположения и не являются независимой разметкой реальных данных. Отдельные интеграционные тесты проверяют конфликты типов/подтипов, отсутствие признаков, запреты, выключенные правила и дубли DMN.

Новые отчёты записывают SHA-256 данных и правил, параметры Java/OS, число доступных процессоров, максимальный heap и объём прогрева. Старые результаты оставлены без изменений; неизвестные параметры среды не восстанавливаются догадками.

## Следующие исследования

- JMH / независимые JVM-процессы и профилирование GC/аллокаций.
- Масштабирование числа правил 14 → 100 → 1 000 при фиксированном числе активов.
- Конфликтные, неполные и зашумлённые входные данные.
- Инкрементальная типизация и многопоточная обработка.
- Повторные измерения на других машинах с полной фиксацией среды.

CI проверяет сборку, корректность 10K, воспроизводимость генератора и Docker runtime. Скорость на GitHub runner не является критерием PASS/FAIL.
