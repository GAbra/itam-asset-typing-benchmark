# Калибровка допустимой разницы приоритетов

Этот этап нужен, чтобы выбрать одно значение для осторожного режима разрешения конфликтов. Он не добавляет веса источникам и не меняет приоритеты существующих правил.

Проверяются значения `20 40 60 80 100 120`. Каждое значение запускается на одних и тех же детерминированных balanced-наборах для уровней шума `clean`, `light`, `moderate`, `stress`, `severe`. Для калибровки используется отдельный seed `20260912`, чтобы не подбирать значение на уже просмотренных данных.

Значение считается допустимым только если одновременно выполняются условия:

- на `clean` результат полностью совпадает с исходной логикой (`window=0`);
- расхождений между BitSet, CEL и DMN нет;
- среди решений, переведённых из FULL AUTO в конфликт/неопределённость, не менее 90% действительно были ошибочными AUTO в сумме по `light/moderate/stress/severe`;
- при `stress` автоматически назначенный подтип сохраняется минимум для 90% объектов;
- при `severe` автоматически назначенный подтип сохраняется минимум для 85% объектов;
- число ошибочных FULL AUTO нигде не увеличивается.

Из всех допустимых значений выбирается то, у которого минимальна суммарная доля ошибочных FULL AUTO на четырёх шумных сценариях. При равенстве выбирается меньшее значение.

Это правило выбора для эксперимента, а не гарантия для production. После выбора значение один раз проверяется на новом seed, который не участвовал в подборе.

Запуск из research-ветки:

```bash
export CALIBRATION_COUNT=200000
export SEED=20260912
export WINDOWS="20 40 60 80 100 120"
export STRICT_GATE=1
sh scripts/run-conflict-window-sweep-docker.sh
```

Главный компактный результат — `sweep-summary.json`. Большие JSONL-файлы и логи по-прежнему не попадают в Git.
